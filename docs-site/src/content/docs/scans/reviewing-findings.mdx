Run bare (`any-doctor` with no doctor argument) and you get the
interactive review: pick the doctors, then the dashboard opens on the
aggregate tree — doctor → check → finding.

## The tree

Expand a doctor to see its checks with counts; expand a check to see its
findings; land on a finding to read the claim and the code. Findings stay
hidden until you expand the check, so a noisy doctor never floods the
screen.

## Keys

| Key | Does |
| --- | --- |
| `up` / `down` (or `k` / `j`) | Move |
| `enter` / `right` | Expand, walk in |
| `left` | Collapse, walk out |
| `a` | Accept the finding as intended |
| `x` | Mark the check not-applicable to this code |
| `v` | Review view — findings with their decision state |
| `u` | Reverse a decision on the selected finding |
| `c` | Copy a fix prompt |
| `q` (or `esc`) | Quit |

## Decisions need reasons

`a` and `x` prompt for a reason, and the reason is required. A reason is
for the future human — including future you — evaluating whether the
decision still holds. "Looks fine" is a rejection of the tool, not a
decision.

Decisions attach to the finding's identity, not its coordinates: code
moving around keeps the decision applied. What resurfaces a finding for
reassessment: the flagged code changing, the doctor's meaning changing,
or duplicate identical occurrences. Details on the
[decisions page](/scans/decisions).

## Copy the work for your agent

`c` copies a fix prompt at whatever level you are on: one finding, a
whole check, or an entire doctor. The prompt carries the finding, the
verify command, and the ready-made `decide` command — paste it into your
agent and the scan-investigate-fix-verify loop runs without you typing
the plumbing.
